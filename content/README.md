# content/ —— 内容知识库

五层结构，每个目录只住一类东西、只有一个消费方。**AI 只读 Knowledge/（R1）；定位只写 `Knowledge/00-定位.md`（R2）；Archive/ 禁止读写（R3）。**

R1 附则：Knowledge/ 里**文件名以 `_` 开头的页只给人看**（如 `_我的版图.md`），注入时被跳过，但仍显示在「知识库」页。

```
content/
├── Knowledge/      # 我理解后写下的规律 —— AI 唯一知识源；00-定位.md 永远注入最前，兼作「设定」页唯一事实源（简介在其「## 账号简介」小节）；`_` 前缀页不进注入
├── Inbox/          # 采集回来的原始内容（采集笔记 → 灵感库；爆款采集 → 每日自动卡片），AI 不读
├── Projects/       # 内容流水线：选题池（立项闸门）→ 发布排期/<账号>/待发布 → 已排期（文件位置即状态）
├── Resources/      # 外部资料：参考文章、对标账号（自动线每天建 5 个新档）、金句原文；只进不改
└── Archive/        # 过时材料（含运营手册 v1），只进不出
```

- 新增知识 = 只在理解之后：把 Inbox/Resources 里消化过的东西写成 Knowledge md，跑 `npm run gen:data`
- 点名引用：创作时指定"参考某篇"，按用户给的文件路径读取，不算破 R1
