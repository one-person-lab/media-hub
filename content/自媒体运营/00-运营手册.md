# 运营手册（模板）

> 这是给开源使用者的**起始模板**，不是范例答案。
> 开源仓库不包含原作者的运营手册——那属于个人 know-how。
> 请把下面每一节替换成你自己的内容，然后改 `config/targets/*.mjs` 里的 `handbookPath` 指过来。
>
> 这份文件会被创作脚本读取（最多 9000 字），作为 AI 写稿的硬约束。

## 三、创作原则

### 三条底线

1. **写具体的，不写正确的** —— "要热爱生活"是结论，"下班绕路买杯想喝的"才是生活
2. **一篇只保留一种核心感受** —— 不要同时塞问题、原因、方法、行动和希望
3. **先让人看见自己，再决定要不要解释** —— 读者自己抵达的感受，比作者总结的更深

### 必须遵守的边界

- ❌ 不虚构个人经历、用户故事、效果或数据
- ❌ 不焦虑羞辱，不攻击具体人群
- ❌ 不提供医疗或心理诊断
- ❌ 不使用"最、绝对、保证、100%"等确定性宣传
- ✅ 引用有出处风险的内容时，只取思想，不冒充逐字原文

### 发布前自检

1. 写的是一个真实感受，还是一个正确道理？
2. 有没有一句或一个画面能让人认出自己？
3. 哪些解释删掉后，画面依然成立？
4. 结尾是在情绪最深处停下，还是作者又出来总结了？

## 四、格式规范

> 这里定的是**硬性格式**，创作脚本会照着执行。

- **总行数**：不超过 20 行正文 + 1 行署名
- **字数**：（你的区间，如 120-200 字）
- **段落**：（如 3-5 段，每段 1-3 行）
- **空行**：段落间 1 个空行，署名前不加空行
- **标点**：（如"正文不使用标点，用换行表达停顿"——按你平台的阅读习惯定）
- **署名**：最后一行统一为 `— （你的账号名）`

### 行数结构示例

```text
第1段（2-3行）     ← 观察对比
                  ← 空行
第2段（3-4行）     ← 反思以前
                  ← 空行
第3段（2-3行）     ← 洞察
                  ← 空行
第4段（2-3行）     ← 行动
— （你的账号名）    ← 署名，紧接第4段
```

## 五、发布与复盘

### 发布时提供

正文 / 标题 / 配文 / 话题标签 / 首评 —— 按平台需要，不强制齐全。

### 标题

- 准确提炼正文最重要的处境或情绪
- 不承诺正文没有提供的答案
- 不为点击率把安静内容改成激烈冲突

### 话题标签

- 保留一个品牌标签：`#（你的品牌标签）`
- 只选与主题真实相关的，不堆砌热门词

### 复盘要记录

发布时间 / 播放或阅读 / 点赞 / 收藏 / 评论 / 关注转化 / 完读率或划走率，
外加三条定性观察：评论区反复提到哪句 / 用户是在夸你还是在讲自己 / 哪类组合最协调。

**还要记转化数据**（填在文章 md 的「## 转化数据」段，一行一个「指标：数值」）：
落地链接带来多少访问、多少下载、多少 star。内容数据只说明传播有多广，
转化数据才说明这条内容**值不值**。链接在发布中心的「落地链接」里复制（已自动带 UTM）。

### 如何使用数据

数据用来发现规律，不用来制造公式。单篇爆款只说明这种表达当时有效，不代表所有内容都要复制。
