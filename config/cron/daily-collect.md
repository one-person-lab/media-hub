# 平台数据每日采集 + 发布状态检测 + 收藏搬运

- **调度**：`47 21 * * *`（Asia/Shanghai，触发后先随机抖动 0~20 分钟再执行）
- **作用域**：仓库根目录
- **产物**：`metrics/raw/<今天日期>.json`（两平台数据快照 + 各平台 `publishedList`）+ `content/Inbox/采集笔记/收藏/` 增量卡片，随后 `npm run gen:data`

## 指令（逐字，重建任务时整段复制）

> 每天采集一次小红书/抖音创作者后台数据 + 五平台「已发布列表」+ 两平台「我的收藏」，为「数据复盘」留存当天快照、为「发布中心」自动判定发布状态、为「灵感库·收藏」追新。
>
> 步骤：
> 1. 先随机等待 0~20 分钟再开始（抖动，避免每天精确同一时刻访问后台的机器特征）。可用 `sleep <随机秒数>` 实现。
> 2. 在项目根目录运行 `npm run collect`（经 ego-browser 用已登录的浏览器抓取创作者后台，结果覆盖写入 metrics/raw/<今天日期>.json，同一天多次运行只保鲜不堆文件）。脚本对导航超时已容错、按平台隔离失败：单平台挂了另一平台的数据仍会落盘；退出码 2 = 至少一个平台本轮失败。
> 3. 再运行 `npm run publish-check`（同样是 ego-browser，逐平台创作者后台采「已发布内容列表」：标题+发布时间+链接，合并写入同一个 metrics/raw/<今天日期>.json 的 platforms[key].publishedList，只改这一个字段不动别的；退出码 2 = 至少一个平台本轮失败）。全程只读列表页，绝不点任何发布/编辑控件。
> 4. 再运行 `npm run favorites`（同样是 ego-browser，把小红书/抖音「我的收藏」整表**增量**搬回灵感库：滚到底翻出收藏列表 → 按 `config/accounts.json` 的 nickname 滤掉自己的笔记 → 已入库的笔记 id 自动跳过 → 新条目落 `content/Inbox/采集笔记/收藏/<平台>/<笔记id>.md`、封面落 `public/inspiration/`。只到索引卡（标题/作者/赞/封面/链接），不搬逐页源图和口播稿——选中要复刻时再走原采集链补源料。整个流程 3~5 分钟属正常。某平台报「没翻到收藏列表」= 该平台登录态失效或被风控，报告即可。）
> 5. 成败判据以产物为准，不信脚本自报：读 `metrics/raw/<今天日期>.json`，确认文件存在、`platforms.xiaohongshu` 与 `platforms.douyin` 的 followers/metrics 有非空读数、各平台 `publishedList` 有条目、`errors` 字段是否为空；收藏以日志行 `[fav:小红书]` / `[fav:抖音]` 的「新入库 N 条」为准，报了条数就去看对应的 md 文件是否真的落盘。
> 6. 若 `errors` 非空或某平台读数全空/publishedList 缺失——【铁律】绝不尝试破解验证码或自动登录，也不改脚本绕过风控，只明确报告「哪个平台本轮没采到、原因是什么（errors 内容）、是否需要在 ego lite 浏览器里重新登录创作者后台」。视频号登录态最容易过期，失效属预期，报告即可。
> 7. 采集成功后运行 `npm run gen:data` 刷新前端数据（dev server 在跑时会随存盘自动刷新，这步是兜底）。
> 8. 成功时简要报告两平台关键指标（小红书观看数、抖音播放量）、日序列条数、各平台 publishedList 采到几条，以及收藏各平台新入库几条。「新入库 0 条」是正常结果（当天没有新收藏），不要为此重跑或放宽门槛。
>
> 约束：只读采集，不做任何发布动作；不修改 collect / publish-check / favorites 脚本逻辑。
