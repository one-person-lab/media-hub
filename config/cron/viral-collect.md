# 爆款采集每日拉取

- **调度**：`40 7 * * *`（Asia/Shanghai，触发后先随机抖动 0~25 分钟再执行）
- **作用域**：仓库根目录
- **产物**：`content/Inbox/爆款采集/<平台>/<id>.md`（含「## 脚本」段）+ 封面与源料 `public/viral/<平台>/`，随后 `npm run gen:data`

## 指令（逐字，重建任务时整段复制）

> 每天自动拉取与账号定位相关的爆款卡片（封面/标题/作者/点赞/链接），小红书与抖音各取一批；采集收尾当场把完整脚本扒进卡里（图文＝逐页图内文字、视频＝口播逐字稿，全程本机 OCR/转写零 token），不再需要人工点「补采脚本」。
>
> 步骤：
> 1. 先随机等待 0~25 分钟再开始（抖动，避免每天精确同一时刻搜同一批关键词的机器特征）。可用 `sleep <随机秒数>` 实现。
> 2. 在项目根目录运行 `npm run viral`（搜索+搬源料约 8~15 分钟，之后自动补扒脚本——视频抽帧 OCR 按片长计时，整体可能到 30~60 分钟，不要中途判定失败）。脚本读 `config/viral.json`：用同一批定位关键词在小红书和抖音搜索 → 滚页拿全量候选（小红书对 URL 上的 sort 参数不响应，返回的是综合排序，所以必须整页取回本地排序，绝不能只取前 N 条）→ 过 minLikes 硬门槛（不足 1 万赞直接丢弃，这是定义不是 bug）→ 过 withinDays 时间窗（发布时间由笔记/视频 ID 反推）→ 按平台各取 Top dailyLimitPerPlatform → 卡片落 `content/Inbox/爆款采集/<平台>/<id>.md`，封面与源料落 `public/viral/<平台>/`。已入库的同一条自动跳过（按 id 去重）。
> 3. 核对脚本：输出末尾应有 `[script] ✓ <id>：image/video N 字` 的逐条记录；报「没拿到源料」的卡留人工入口（工作台点「补采脚本」），不算失败。跑完运行 `npm run gen:data` 刷新工作台数据，输出里应看到「N 条爆款采集」的计数变化。
> 4. 检查输出：
>    - 若某关键词报「结果始终没出现」或「抓取失败」，或某平台候选为 0 —— 很可能是 ego lite 浏览器里该平台登录态失效或出现风控验证。【铁律】绝不尝试破解验证、不自动登录、不改脚本绕过风控、不加重试，只报告「需要在 ego lite 浏览器里重新登录小红书/抖音」。
>    - 若某平台报「不足 10000 赞筛掉 N 条 → 达标 0」，这是正常结果：当天该赛道没有新爆款。【不要】为了让条数好看去放宽 `config/viral.json` 的 minLikes 或 withinDays、不要改关键词、不要重试。门槛口径归用户拍板。
> 5. 成功时简要报告：各平台新入库几条、标题与点赞数、命中关键词；以及哪个平台本轮 0 条及原因。
>
> 约束：只读浏览搜索结果页，不做任何发布/点赞/关注动作；不改 `config/viral.json` 的关键词与门槛；不动 `content/Inbox/采集笔记/`（那是手动的灵感库）。
